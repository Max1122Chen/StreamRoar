# 暂存区验收

评审对象是 `git diff --cached`，包含功能代码和 `docs/` 文档改动。评审保持只读，不修改代码、文档或暂存区。
用户明确要求修复后可编辑工作区，所有修复保持未暂存，不执行 git add 或 commit。

## 取证范围

用 `git diff --cached --name-status` 定位改动，检查项目自有功能代码、配置逻辑和 `docs/` 的新增、修改、删除与重命名。
新增文件或需要全文时用 `git show :路径` 读取暂存版本；存在未暂存修改时避免将工作区内容误当成提交内容。
相关调用方可作为判断依据，但只报告此次 staged 改动引入的可操作问题。

美术、第三方、生成文件不做逐行风格评审；当字段/GUID/序列化或行为树变化影响功能时，检查关联资产和加载证据。
没有 staged 改动则直接说明。未运行 Unity 时明确运行验证边界，不把静态搜索写成运行通过。

## 文档评审

按 AGENTS.md 的文档规则评审本次暂存的 `docs/` 改动；相关模块 README、API 参考与实现按需取证。
纯文档提交同样评审，不因没有 C# 改动跳过。重点检查：

- 说明与本次暂存版本的代码、资产和配置一致，不把未暂存实现、未来计划或已删除类型当作现状。
- 路径、符号、链接与引用有效；删除或重命名文档后，相关入口没有悬空引用。
- 区分当前实现、计划、历史记录和已验证行为；不将静态检查或旧验证记录写成本次运行通过。
- 遵循按需维护原则，没有重复规则、矛盾要求、无关扩写或新增强制报告、日志与多文档同步负担。

功能变更已使相关说明失真但未同步时，报告具体差异；不因缺少形式化文档更新而机械扣分。
只报告本次改动引入或直接造成的问题，不借评审扩展成全量文档整改，也不自动编辑文档。

## 输出

用中文简述改动，再按 P0–P3 列真实问题，给出位置、触发条件、影响和修改建议。
重点关注行为正确性、所有权、初始化、事件和池生命周期、配置兼容与序列化引用。
不为凑数报告个人风格、无害 TODO 或推测性问题。

保留整体 `x/10` 评分和一句提交结论；问题已有严重级别，不再逐条打分或强制附带表扬段落。
文档问题与代码问题使用同一优先级列表；简述已检查的 docs 范围，无文档改动时无需另列一节。
最后给一个 `feat: 描述`、`fix: 描述`、`refactor: 描述` 或 `docs: 描述` 的中文 Commit 标题，标题不加括号或方括号。
